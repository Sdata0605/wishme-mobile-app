Answer to Replit's 3 Questions
The Core Issue: Two Different UUIDs
Every user has two UUIDs:

Auth UUID — auth.users.id (also stored as profiles.user_id)
Profile UUID — profiles.id (a separate auto-generated UUID)
Both wallet_transactions.user_id and referral_transactions.referrer_id store the Profile UUID (profiles.id), NOT the Auth UUID.

How the Web App Resolves This
The web app's auth hook (useAuth) fetches the full profile row on login:

auth.users.id → profiles.user_id (match) → returns profiles.id
Then all wallet queries use profile.id:


// Wallet transactions — uses profile.id
supabase.from('wallet_transactions')
  .select('*')
  .eq('user_id', profile.id)  // ← This is profiles.id, NOT auth.users.id

// Referral transactions — uses profile.id  
supabase.from('referral_transactions')
  .select('*')
  .eq('referrer_id', profile.id)  // ← Also profiles.id
