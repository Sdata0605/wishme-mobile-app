/bookings Page — Complete Technical Reference for Replit Mobile App
Purpose
This page is the unified order history dashboard where users see ALL their past orders across 12 different service categories. It's read-only — no creation happens here, only viewing status and media playback.

Authentication
Requires logged-in user. Uses useAuth() hook to get profile.id (UUID from profiles table). All queries filter by user_id = profile.id.

Base URL for all Supabase queries
https://eqikeuqwbphwongtfzhe.supabase.co
Headers for all requests:


{
  "apikey": "<SUPABASE_ANON_KEY>",
  "Authorization": "Bearer <user_access_token>",
  "Content-Type": "application/json"
}
DATA FETCHING — 12 Parallel Queries
All 12 queries run in parallel via Promise.all. Each is a Supabase .select() with .eq('user_id', profile.id), .order('created_at', { ascending: false }), .limit(50).

Tab 1: Celebrity Bookings (Video/Ad orders)
GET /rest/v1/bookings?select=*,celebrities:celebrity_id(name,image_url,category)&user_id=eq.<profile_id>&order=created_at.desc&limit=50
Response row shape:


{
  "id": "uuid",
  "user_id": "uuid",
  "celebrity_id": "uuid",
  "service_type": "video_wish | image_promotion | video_promotion | general_wish | text_message",
  "status": "pending | confirmed | completed | video_sent | sent | cancelled | failed",
  "generation_status": "null | script_generating | video_generating | downloading | uploading | completed | failed | timeout",
  "video_status": "null | processing | ready | failed | timeout",
  "video_file_key": "string (B2 file path) | null",
  "video_url": "string (direct URL fallback) | null",
  "message": "string (JSON or plain text)",
  "final_price": 2500,
  "created_at": "2026-03-20T...",
  "generation_error": "string | null",
  "celebrities": {
    "name": "Virat Kohli",
    "image_url": "https://...",
    "category": "Cricket"
  }
}
Status Logic (priority order — first match wins):

Condition	Display Label	Animated?
status === 'cancelled'	❌ Cancelled	No
video_status === 'failed' OR generation_status === 'failed'	⚠️ Failed	No
generation_status === 'timeout'	⚠️ Timed Out	No
status === 'completed'	✅ Completed	No
status === 'video_sent' OR 'sent'	📤 Delivered to You	No
generation_status === 'completed' AND video_status === 'ready'	🎥 Video Ready	No
generation_status === 'uploading'	⬆️ Uploading Video	Yes (pulse)
generation_status === 'downloading'	⬇️ Processing Video	Yes (pulse)
generation_status === 'video_generating'	🎬 Creating Video...	Yes (pulse)
generation_status === 'script_generating'	🤖 Writing Script...	Yes (pulse)
status === 'confirmed'	✅ Confirmed — In Queue	No
status === 'pending'	⏳ Awaiting Confirmation	No
Video Playback:

If video_file_key exists AND video_status === 'ready': construct URL as https://f005.backblazeb2.com/file/wishmetoday/<video_file_key>
Fallback: use video_url directly if it starts with http
Neither set: show "Video is being processed..."
6-Step Order Timeline (shown when status !== 'pending'):

Booking Placed (always ✓)
Confirmed by Team (status !== 'pending')
Script Generated (generation_status in ['video_generating','downloading','uploading','completed'])
Video Being Created (generation_status in ['downloading','uploading','completed'])
Video Ready (video_status === 'ready')
Delivered (status in ['video_sent','sent','completed'])
Message Parsing: The message field is JSON:


{
  "requestDetails": { "recipientName": "Rahul", "occasion": "Birthday", "message": "Happy bday!" },
  "creativeGuidelines": { "toneAndStyle": "Fun", "goal": "Surprise" },
  "scriptBuilder": { "talkingPoints": "...", "exactScript": "...", "generatedScript": "..." }
}
Parse with JSON.parse(), fallback to raw string.

REAL-TIME SUBSCRIPTIONS
Two Supabase Realtime channels auto-refresh data:

Bookings channel: listens for UPDATE on bookings table filtered by user_id
Music channel: listens for UPDATE on music_generations table filtered by user_id
On any update event, calls fetchAllBookings() to refresh ALL tabs.

For mobile: use Supabase Realtime client or poll every 30 seconds as fallback.
