Step 3: Post-Login Routing Decision (in handleSignIn)
After signIn() returns without error, the code runs this three-tier routing check:


// 1. Get fresh user
const { data: { user: currentUser } } = await supabase.auth.getUser();

// 2. Fetch profile
const { data: profileData } = await supabase
  .from('profiles')
  .select('id, role, plan')
  .eq('user_id', currentUser.id)
  .maybeSingle();

// 3. Route based on role hierarchy
if (profileData.role === 'admin') {
  navigate('/admin');                    // Admin dashboard
} else {
  // Check celebrities table -- THIS IS THE KEY CHECK
  const { data: celebrityData } = await supabase
    .from('celebrities')
    .select('id')
    .eq('profile_id', profileData.id)   // profile.id, NOT user_id
    .maybeSingle();

  if (celebrityData) {
    navigate('/celebrity-dashboard');     // <-- John goes HERE
  } else if (profileData.plan === 'premium' || profileData.plan === 'elite') {
    navigate('/dashboard');
  } else {
    // Basic plan user -- show plan selection or dashboard
    const skipped = sessionStorage.getItem('plan_skipped_this_session');
    navigate(skipped ? '/dashboard' : '/plan?redirected=true');
  }
}

Celebrity check	GET /rest/v1/celebrities?profile_id=eq.{profile_id}&select=id with Bearer token
Critical FK	celebrities.profile_id references profiles.id (NOT auth.users.id)
Session header	All API calls: Authorization: Bearer {access_token} + apikey: {anon_key}
