Here is a complete technical specification of the "Book a Service" system for Replit mobile app integration.

BOOK A SERVICE — Complete Technical Specification
Overview
When a user visits a celebrity profile (/celebrity/{id}), they see a "Book a Service" section with 3 service cards. Clicking "Book Now" navigates to a 6-step booking wizard at /booking/{celebrityId}?service={serviceId}.

SERVICE CARDS (Entry Point)
Component: BookAServiceSection.tsx UI Components: Card, CardContent, Button, Badge, Lucide icons (Heart, ImageIcon, Video, Lock)

3 Services offered:

Service ID	Title	Icon	Price Key (from celebrity.service_prices JSONB)	Default Price
wish	Wish a Friend	Heart (pink)	general_wish	₹5,000
ad	Make an Ad	ImageIcon (blue)	image_promotion	₹25,000
video	Make a Video Promo	Video (purple)	video_promotion	₹50,000
Gate Logic: If user is NOT subscribed (celebrity_favorites.status != 'active'), prices are hidden behind a Lock icon and button says "Subscribe to Book". If subscribed, prices show and button says "Book Now".

Navigation: handleBookNow(serviceId) navigates to:

/booking/{celebrity.id}?service={serviceId}
6-STEP BOOKING WIZARD
Route: /booking/{celebrityId}?service=wish|ad|video Layout: 75% main content (steps) + 25% sticky sidebar (celebrity info + price summary)

Sidebar always shows: celebrity avatar, name, rating, service title, base price, discount (if plan active), service fee (10%), and total.

Progress bar: Linear Progress component showing (currentStep / 6) * 100%

Shared state object passed between all steps:


{
  "serviceType": "wish|ad|video",
  "requestDetails": {},
  "deliveryType": "video",
  "creativeGuidelines": {},
  "scriptBuilder": {}
}
STEP 1: Request Details
Component: RequestDetailsStep.tsx UI Components: Card, Input, Label, RadioGroup, RadioGroupItem, Textarea, Select, SelectContent, SelectItem, Globe icon, Loader2 icon

Different forms per service type:

For service=video:
Field	Component	Required	Validation
Video Type	RadioGroup: "Marketing" / "Business event"	YES	must select one
Business Name	Input	YES	non-empty
Business Pronunciation	Input	NO	—
Video Language	Select dropdown	NO (default: en-US)	—
For service=wish:
Field	Component	Required	Validation
Recipient Name	Input	YES	non-empty
Relationship	Input	NO	—
Occasion	Input	YES	non-empty
Special Message	Textarea (4 rows)	NO	—
Video Language	Select dropdown	NO (default: en-US)	—
For service=ad:
Field	Component	Required	Validation
Business/Product Name	Input	YES	non-empty
Ad Description	Textarea (4 rows)	NO	—
API Call — Language Fetch (only for video and wish services):

POST /functions/v1/heygen-get-languages

Headers:
  Authorization: Bearer {access_token}
  apikey: {anon_key}

No payload needed.

Response:
{
  "languages": [
    { "language": "English", "locale": "en-US" },
    { "language": "Hindi", "locale": "hi-IN" },
    ...38 total languages
  ]
}
If this fails, a hardcoded fallback list of 38 languages is used.

STEP 2: Delivery Type
Component: DeliveryTypeStep.tsx UI Components: Card, CardDescription, RadioGroup (hidden radio + styled Label), Video/ImageIcon/CheckCircle icons

3 Options:

Value	Title	Description
video	Video Message	Personalized AI-generated video from the celebrity
card	Greeting Card	Beautiful AI-generated greeting card
both	Video + Card	Get both video message and greeting card
No API calls. Selection stored as bookingData.deliveryType.

STEP 3: Creative Guidelines
Component: CreativeGuidelinesStep.tsx UI Components: Card, Select (dropdown), Textarea (with char counter /500), Checkbox list

Field	Component	Required	Max Length
Goal	Select dropdown (9 options + "Other")	YES	—
Goal Other	Textarea (if "Other" selected)	—	500
Tone & Style	Textarea	NO	500
Filming Requirements	Textarea (only for video service)	NO	500
Things to Avoid	Checkbox list (8 options + "Other")	NO	—
Other Info	Textarea	NO	500
Goal options: "Birthday wish for a friend", "Anniversary celebration", "Product launch promotion", "Brand ambassador campaign", "Social media content", "Event invitation", "Thank you message", "Motivational message", "Other"

Things to avoid options: "Visible brand logos", "Political references", "Religious content", "Controversial topics", "Competitor mentions", "Profanity or explicit content", "Alcohol or tobacco products", "Other"

No API calls. All data stored locally in bookingData.creativeGuidelines.

STEP 4: Script Builder
Component: ScriptBuilderStep.tsx UI Components: Card, RadioGroup, Textarea (with /1500 counter), Input (/150 counter), Button with Wand2 icon, Loader2

Two modes depending on service:

For service=ad (simplified):
Field	Component	Max Length
Ad Description	Textarea	1500
Image Style Preferences	Textarea	300
For service=video or service=wish:
Field	Component	Required
Script Type	RadioGroup: "Talking points" / "Exact script"	YES
Talking Points	Textarea (if talking_points)	YES
Exact Script	Textarea (if exact_script)	YES
Required Lines	Input	NO
AI Script Generation API (triggered by "Generate Script" button):

POST /functions/v1/generate-script

Headers:
  Authorization: Bearer {access_token}
  apikey: {anon_key}

Payload:
{
  "prompt": "Generate a {serviceType} script for {celebrity.name} based on the following details:\n\nService Type: {serviceType}\nCelebrity: {celebrity.name} ({celebrity.category})\nTalking Points: {talkingPoints}\nRequired Lines: {requiredLines}\nRequest Details: {JSON bookingData.requestDetails}\nCreative Guidelines: {JSON bookingData.creativeGuidelines}\n\nCreate a natural, engaging script...\n\nIMPORTANT: Write the ENTIRE script in {language}."
}

Response:
{
  "script": "Hey everyone! I'm {celebrity.name} and I'm here to tell you about..."
}
Generated script shows in a bordered preview box with a "Use This Script" button that copies it into the active textarea.

STEP 5: Review
Component: ReviewStep.tsx UI Components: Card, Badge, Alert, AlertDescription, BadgePercent icon, Edit icon

Sections displayed:

Discount Alert (if plan active): green banner showing "X% PLAN Discount Applied! You save ₹Y"
Request Details: Shows collected data from Step 1 in Badge + text format
Creative Guidelines: Shows goal, tone & style from Step 3
Script/Content: Shows talking points or exact script from Step 4
Pricing Summary:
Service price (with strikethrough if discounted)
Platform Fee (10% of discounted price)
Total
Price calculation (client-side):


basePrice = celebrity.service_prices[serviceKey]
discountedPrice = basePrice * (1 - discountPercentage/100)  // from usePlanDiscount hook
serviceFee = Math.round(discountedPrice * 0.1)
total = discountedPrice + serviceFee
No API calls. Pure display step.

STEP 6: Checkout
Component: CheckoutStep.tsx UI Components: Card, Checkbox, Separator, Alert, Button, RecipientScheduling sub-component, PaymentMethodSelector modal

Sections:

Discount Alert (same as Review)
Order Summary (same price breakdown)
Gift Scheduling (RecipientScheduling): optional toggle to schedule delivery to a recipient
Fields: name, email, phone, date (Calendar popover), time (Select with hourly slots)
Delivery Info: Shows celebrity.delivery_time
Wallet Balance: Shows current balance from useWalletBalance() hook
Terms Checkbox: Must agree before paying
Pay Button: Opens PaymentMethodSelector modal
Payment Method Modal (PaymentMethodSelector.tsx): Dialog with two buttons — "Wallet" and "Razorpay"

WALLET PAYMENT FLOW:
Step 1: INSERT into bookings
POST /rest/v1/bookings

Payload:
{
  "celebrity_id": "{celebrity.id}",
  "user_id": "{profile.id}",
  "service_type": "video_wish|image_promotion|video_promotion",
  "original_price": 5000,
  "discount_amount": 500,
  "final_price": 4950,
  "status": "pending",
  "message": "{JSON.stringify(bookingData)}",
  "instructions": "{creativeGuidelines.goal}",
  "delivery_type": "video|card|both",
  "generated_prompt": "{scriptBuilder.generatedScript}"
}

Response: { "id": "uuid", ...booking fields }
Step 2 (optional): INSERT into scheduled_messages (if gift scheduling enabled)
POST /rest/v1/scheduled_messages

Payload:
{
  "user_id": "{profile.id}",
  "recipient_email": "friend@email.com",
  "recipient_whatsapp": "+919876543210",
  "channel": "email|whatsapp|both",
  "scheduled_at": "2026-04-01T09:00:00.000Z",
  "order_id": "{booking.id}",
  "order_type": "booking",
  "payload": {
    "first_name": "Recipient Name",
    "service_type": "wish",
    "celebrity_name": "Celebrity Name",
    "order_url": "https://wishmefinal.lovable.app/booking-summary?bookingId={booking.id}"
  }
}
Step 3: INSERT into wallet_transactions
POST /rest/v1/wallet_transactions

Payload:
{
  "user_id": "{profile.id}",
  "transaction_type": "booking",
  "amount": 4950,
  "status": "completed",
  "payment_method": "wallet",
  "transaction_details": {
    "booking_id": "{booking.id}",
    "celebrity_id": "{celebrity.id}",
    "service_type": "wish",
    "base_price": 5000,
    "discount_percentage": 10,
    "discount_amount": 500,
    "plan": "gold"
  }
}
Step 4: INSERT into payment_transactions + UPDATE booking
POST /rest/v1/payment_transactions

Payload:
{
  "wishme_payment_id": "WM2603ABCDE",
  "user_id": "{profile.id}",
  "amount": 4950,
  "payment_method": "wallet",
  "service_type": "booking",
  "booking_id": "{booking.id}",
  "description": "Booking for {celebrity.name} - wish",
  "status": "completed",
  "paid_at": "2026-03-29T10:00:00.000Z"
}

Then: PATCH /rest/v1/bookings?id=eq.{booking.id}
Body: { "wishme_payment_id": "WM2603ABCDE" }
Navigate to: /booking-summary?bookingId={id}&paymentId={wishmePaymentId}

RAZORPAY PAYMENT FLOW:
Step 1: INSERT into bookings (same as wallet flow, status='pending')

Step 2: POST /functions/v1/create-razorpay-order
Payload:
{
  "amount": 4950,
  "currency": "INR",
  "receipt": "booking_{booking.id}",
  "notes": {
    "booking_id": "{booking.id}",
    "celebrity_id": "{celebrity.id}",
    "service_type": "wish"
  }
}

Response:
{
  "id": "order_XXXXX",
  "amount": 495000,
  "currency": "INR",
  "key_id": "rzp_live_XXXXX"
}

Step 3: Open Razorpay SDK with key_id, order_id, amount

Step 4: On success, POST /functions/v1/verify-razorpay-payment
Payload:
{
  "razorpay_payment_id": "pay_XXXXX",
  "razorpay_order_id": "order_XXXXX",
  "razorpay_signature": "signature_hash",
  "booking_id": "{booking.id}"
}

Response:
{
  "verified": true,
  "wishme_payment_id": "WM2603FGHIJ"
}
Navigate to: /booking-summary?bookingId={id}&paymentId={wishmePaymentId}

SCREEN FLOW DIAGRAM

Celebrity Profile (/celebrity/{id})
  └── Book a Service Section
       ├── Wish a Friend ──┐
       ├── Make an Ad ──────┤
       └── Make a Video ────┘
                            │
                    /booking/{id}?service={type}
                            │
              ┌─────────────┼─────────────┐
              │  6-Step Wizard             │
              │  Step 1: Request Details   │
              │  Step 2: Delivery Type     │
              │  Step 3: Creative Guide    │
              │  Step 4: Script Builder    │
              │  Step 5: Review            │
              │  Step 6: Checkout          │
              │       ├── Wallet Payment   │
              │       └── Razorpay Payment │
              └─────────────┼─────────────┘
                            │
              /booking-summary?bookingId={id}
                            │
              (status = 'pending' — awaits admin approval)
                            │
              Admin approves → status = 'confirmed'
                            │
              AI generates video → status = 'video_ready'
                            │
              Admin sends → status = 'video_sent'
                            │
              User views on /bookings page
IMPORTANT NOTES FOR MOBILE
All bookings start as status='pending' — admin must approve before processing
Service type mapping: wish → video_wish, ad → image_promotion, video → video_promotion (in DB)
Price formula: total = discountedPrice + Math.round(discountedPrice * 0.1)
WishMe Payment ID format: WM + YYMM + 5 random alphanumeric chars
For Razorpay on mobile, use the Razorpay React Native SDK instead of the web checkout
The generate-script Edge Function uses Google Gemini 2.0 Flash behind the scenes
