WALLET PAGE — DATA FETCHING SPECIFICATION FOR REPLIT
1. REFERRAL EARNINGS CARD
Purpose: Show total earned from referrals, number of referred friends, and pending referrals.

When fetched: On mount, when profile.id is available.

Endpoint: Supabase REST — referral_transactions table

Query:

GET /rest/v1/referral_transactions?referrer_id=eq.{profile.id}&select=*
Headers:
  apikey: {ANON_KEY}
  Authorization: Bearer {user_jwt}
Response — array of objects:


[
  {
    "id": "uuid",
    "referrer_id": "uuid",
    "referred_id": "uuid",
    "booking_id": "uuid-or-any-service-id",
    "commission_level": 1,
    "commission_amount": 150,
    "commission_percentage": 10,
    "order_type": "booking",
    "status": "completed",
    "created_at": "2026-03-25T10:00:00Z"
  }
]
Client-side processing to build stats:


const completed = data.filter(t => t.status === 'completed');
const pending = data.filter(t => t.status === 'pending');
const uniqueUsers = new Set(completed.map(t => t.referred_id));

referralStats = {
  totalEarned: completed.reduce((sum, t) => sum + (t.commission_amount || 0), 0),
  friends: uniqueUsers.size,       // count of unique referred users
  pending: pending.length           // count of pending referral transactions
};
UI mapping:

Stat	Value	Display
Total Earned	referralStats.totalEarned	₹{totalEarned.toLocaleString()}
Friends Referred	referralStats.friends	number
Pending	referralStats.pending	number
2. RECENT ACTIVITY (TRANSACTION LIST)
Purpose: Show a merged, time-sorted list of all wallet debits/credits AND referral commissions.

When fetched: On mount, when profile.id is available.

Three parallel queries are fired:

Query A — Wallet Transactions (main ledger)
GET /rest/v1/wallet_transactions?user_id=eq.{profile.id}&select=*&order=created_at.desc
Response:


[
  {
    "id": "uuid",
    "user_id": "uuid",
    "transaction_type": "booking",
    "amount": -999,
    "status": "completed",
    "payment_method": "wallet",
    "transaction_details": { "razorpay_order_id": "..." },
    "created_at": "2026-03-27T14:00:00Z",
    "description": "Booking for Celebrity X"
  }
]
Possible transaction_type values:

Credits: deposit, admin_credit, commission_earning
Debits: booking, music_generation, music_download, greeting_card_generation, celebrity_subscription, image_promotion, ugc_video, photo_wish, celebrity_call, voice_call, plan_upgrade, service_payment, debit, withdrawal
Query B — Referral Transactions (commissions)
GET /rest/v1/referral_transactions?referrer_id=eq.{profile.id}&select=*&order=created_at.desc
Same response as Section 1 above.

These are transformed before merging:


refTxData.map(tx => ({
  ...tx,
  source: 'referral',
  transaction_type: 'referral_commission',  // force this type
  amount: tx.commission_amount,              // use commission_amount as amount
  status: tx.status
}))
Query C — Payment Transactions (for WishMe Payment ID lookup)
GET /rest/v1/payment_transactions?user_id=eq.{profile.id}&select=wishme_payment_id,user_id,amount,paid_at&order=paid_at.desc
Response:


[
  {
    "wishme_payment_id": "WM2603XYZAB",
    "user_id": "uuid",
    "amount": 999,
    "paid_at": "2026-03-27T14:00:00Z"
  }
]
This is NOT displayed as a list. It builds a lookup map so each wallet transaction can show its WishMe Payment ID:


const lookup: Record<string, string> = {};
ptData.forEach(pt => {
  const key = `${Math.abs(pt.amount)}`;
  if (!lookup[key]) lookup[key] = pt.wishme_payment_id;
});
// Usage: lookup["999"] → "WM2603XYZAB"
3. MERGING & SORTING
After all 3 queries return, merge wallet + referral into one array, sorted newest-first:


const allTransactions = [
  ...walletTxData.map(tx => ({ ...tx, source: 'wallet' })),
  ...referralTxData.map(tx => ({
    ...tx,
    source: 'referral',
    transaction_type: 'referral_commission',
    amount: tx.commission_amount,
    status: tx.status
  }))
].sort((a, b) => new Date(b.created_at).getTime() - new Date(a.created_at).getTime());

5. FILTERING & PAGINATION
Default: Show first 10 transactions
"Show All" toggle: showAllTx boolean shows all
Payment ID search: Filter by paymentIdSearch string matching against the WM ID lookup
Filtered list logic:

const filteredTx = transactions.filter(tx => {
  if (!paymentIdSearch) return true;
  const wmId = paymentTxLookup[`${Math.abs(tx.amount)}`] || '';
  return wmId.toLowerCase().includes(paymentIdSearch.toLowerCase());
});
const displayedTx = showAllTx ? filteredTx : filteredTx.slice(0, 10);
