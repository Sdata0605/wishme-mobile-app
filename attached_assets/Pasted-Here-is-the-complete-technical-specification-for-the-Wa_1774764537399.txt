Here is the complete technical specification for the Wallet Deposit & Withdrawal system for Replit mobile integration.

/wallet Page — Deposit & Withdrawal Technical Specification
1. PAGE PURPOSE
The Wallet page lets users view their balance, deposit money via Razorpay, view transaction history (wallet + referral), search by WishMe Payment ID, and navigate to referrals. The Withdraw button exists but is currently a UI-only placeholder with no backend logic for regular users.

2. DEPOSIT FLOW (Razorpay — Fully Functional)
The deposit is a 3-step process: Create Order → Pay via Razorpay → Verify & Record.

Step 1: Create Razorpay Order
Endpoint: POST /functions/v1/create-razorpay-order

Headers:

Authorization: Bearer <user_jwt>
apikey: <supabase_anon_key>
Content-Type: application/json
Payload:


{
  "amount": 1000,
  "currency": "INR",
  "receipt": "wallet_{profile_id}_{timestamp}",
  "notes": {
    "user_id": "{profile_id}",
    "type": "wallet_deposit"
  }
}
Response (success):


{
  "id": "order_PxxxxxxxxxxxxX",
  "entity": "order",
  "amount": 100000,
  "amount_paid": 0,
  "amount_due": 100000,
  "currency": "INR",
  "receipt": "wallet_abc123_1711700000",
  "status": "created",
  "key_id": "rzp_test_SWcF0o0gYq1y2O"
}
Notes:

amount in payload is in rupees (integer). The Edge Function converts to paise (×100) for Razorpay.
key_id is returned from the server — use it to initialize the Razorpay SDK on mobile.
Minimum deposit enforced client-side: ₹100.
Receipt is auto-truncated to 40 chars if too long.
Step 2: Open Razorpay Payment
On web, this uses the Razorpay Checkout.js SDK. For mobile, use the Razorpay React Native SDK or Flutter SDK.

Razorpay SDK Config:


{
  "key": "{key_id from Step 1}",
  "amount": 100000,
  "currency": "INR",
  "name": "WishMe",
  "description": "Add money to wallet",
  "order_id": "{order_id from Step 1}",
  "prefill": {
    "name": "User Full Name",
    "email": "user@email.com",
    "contact": "+919876543210"
  },
  "theme": {
    "color": "#EC4899"
  }
}
On Success, Razorpay returns:


{
  "razorpay_order_id": "order_PxxxxxxxxxxxxX",
  "razorpay_payment_id": "pay_PxxxxxxxxxxxxX",
  "razorpay_signature": "hmac_sha256_signature_string"
}
On Failure, Razorpay returns:


{
  "error": {
    "code": "BAD_REQUEST_ERROR",
    "description": "Payment was cancelled by user",
    "source": "customer",
    "step": "payment_authentication"
  }
}
Step 3: Verify Payment & Record Transaction
Endpoint: POST /functions/v1/verify-razorpay-payment

Headers:

Authorization: Bearer <user_jwt>
apikey: <supabase_anon_key>
Content-Type: application/json
Payload:


{
  "razorpay_order_id": "order_PxxxxxxxxxxxxX",
  "razorpay_payment_id": "pay_PxxxxxxxxxxxxX",
  "razorpay_signature": "hmac_sha256_signature_string"
}
Response (success):


{
  "success": true,
  "message": "Payment verified successfully",
  "wishme_payment_id": "WM2503A7K3P"
}
Response (failure):


{
  "error": "Payment signature verification failed"
}
What happens server-side on verification:

Computes HMAC-SHA256(razorpay_order_id|razorpay_payment_id, RAZORPAY_KEY_SECRET) and compares with razorpay_signature.
On failure: triggers a payment_failed notification.
Step 3b: Record in Database (Client-Side After Verify)
After successful verification, the client inserts two records:

Insert 1 — wallet_transactions:

POST /rest/v1/wallet_transactions

{
  "user_id": "{profile_id}",
  "transaction_type": "deposit",
  "amount": 1000,
  "status": "completed",
  "payment_method": "razorpay",
  "transaction_details": {
    "razorpay_order_id": "order_Pxxxx",
    "razorpay_payment_id": "pay_Pxxxx"
  }
}
Important: The database trigger trigger_update_wallet_balance on wallet_transactions automatically updates profiles.wallet_balance when transaction_type = 'deposit' and status = 'completed'.

Insert 2 — payment_transactions (central ledger):

POST /rest/v1/payment_transactions

{
  "wishme_payment_id": "WM2503A7K3P",
  "user_id": "{profile_id}",
  "amount": 1000,
  "payment_method": "razorpay",
  "service_type": "deposit",
  "razorpay_payment_id": "pay_Pxxxx",
  "razorpay_order_id": "order_Pxxxx",
  "description": "Wallet deposit of ₹1000",
  "status": "completed",
  "paid_at": "2026-03-29T10:00:00.000Z"
}
The wishme_payment_id is generated client-side using format: WM + YYMM + 5 random alphanumeric chars (excluding confusing chars like O, 0, I, 1).

3. WITHDRAWAL (User — UI Placeholder Only)
The "Withdraw" button on the /wallet page is non-functional for regular users. It renders but has no onClick handler — it's purely visual.

For celebrities, withdrawal is functional via the Celebrity Dashboard → Wallet Tab (/celebrity-dashboard). Here's how it works:

Celebrity Withdrawal Flow:
Step 1: Load bank details

GET /rest/v1/bank_details?user_id=eq.{profile_id}&order=is_default.desc
Step 2: Submit payout request

POST /rest/v1/payout_requests

{
  "celebrity_id": "{celebrity_id}",
  "profile_id": "{profile_id}",
  "requested_amount": 5000,
  "bank_account_number": "****1234",
  "bank_name": "HDFC Bank",
  "ifsc_code": "HDFC0001234",
  "account_holder_name": "Celebrity Name",
  "status": "pending"
}
Step 3: Deduct from celebrity balance

PATCH /rest/v1/celebrities?id=eq.{celebrity_id}

{
  "available_balance": {current_balance - requested_amount}
}
Step 4: Admin processes via /admin → Wallet Management tab (approve/reject).

4. BALANCE FETCHING
Real-time balance via useWalletBalance hook:

GET /rest/v1/profiles?id=eq.{profile_id}&select=wallet_balance
Plus a Realtime subscription on profiles table filtered by id=eq.{profile_id} — listens for wallet_balance changes via Postgres Changes channel.

5. TRANSACTION HISTORY
Wallet transactions:

GET /rest/v1/wallet_transactions?user_id=eq.{profile_id}&select=*&order=created_at.desc
Referral transactions:

GET /rest/v1/referral_transactions?referrer_id=eq.{profile_id}&select=*&order=created_at.desc
Payment ID lookup (for search):

GET /rest/v1/payment_transactions?user_id=eq.{profile_id}&select=wishme_payment_id,user_id,amount,paid_at&order=paid_at.desc
Both wallet and referral transactions are merged client-side, sorted by created_at descending.

6. TRANSACTION TYPE MAPPING
transaction_type	Label	Credit/Debit
deposit	Wallet Top-up	Credit (+)
admin_credit	Admin Credit	Credit (+)
referral_commission	Referral Bonus	Credit (+)
commission_earning	Commission Earned	Credit (+)
booking	Video Shoutout	Debit (-)
music_generation	Music Generation	Debit (-)
greeting_card_generation	Greeting Card	Debit (-)
celebrity_subscription	Celebrity Subscription	Debit (-)
image_promotion	Image Promotion	Debit (-)
photo_wish	Photo Wish	Debit (-)
voice_call	Voice Call	Debit (-)
ugc_video	UGC Video	Debit (-)
plan_upgrade	Plan Upgrade	Debit (-)

    |                              |                              |                     |
    |--- Open Razorpay Native SDK -------------------------------->                     |
