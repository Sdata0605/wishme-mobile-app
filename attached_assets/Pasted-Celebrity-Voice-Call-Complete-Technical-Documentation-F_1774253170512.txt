When scheduledAt is null or absent → immediate call. When it's an ISO string like "2026-03-25T10:00:00.000Z" → scheduled call.

Backend Flow (vapi-celebrity-call Edge Function)
Validates auth JWT → gets user profile
Checks recipientName, recipientPhone, occasion, celebrityId, voiceId, senderName are present — if any missing, returns 400 "Missing required fields"
Picks phoneNumberId = celebrityPhoneId (from payload) or VAPI_PHONE_NUMBER_ID env var
Checks wallet: profile.wallet_balance >= price
Formats phone to +91XXXXXXXXXX
Builds GPT system prompt using all personalization fields
If scheduledAt is set → saves to DB with call_status: 'scheduled', deducts wallet, returns
If immediate → calls POST https://api.vapi.ai/call with the full Vapi payload
On success → deducts wallet, records wallet_transactions, inserts into voice_call_wishes with call_status: 'initiated'
Returns { success: true, callId: "vapi-call-id" }
The "Missing Required Fields" Error on Mobile
The backend validation at line 76-83 of the edge function checks:


if (!recipientName || !recipientPhone || !occasion || !celebrityId || !voiceId || !senderName)
The most likely cause on mobile is that occasion is not being sent. The <Select> component sometimes doesn't fire onValueChange properly on mobile touch. The occasion state starts as '' (empty string), which is falsy. If the dropdown doesn't register the tap, occasion stays empty and passes client validation (line 167 checks !occasion which catches empty string) — but if it somehow passes, the backend rejects it.

The button is also disabled unless all required fields are filled (line 660), so if you're seeing the button enabled but getting the error, it suggests the client-side state has values but the payload arriving at the backend is missing something — potentially a race condition or the selectedCelebrity.vapi_voice_id being null/undefined in the database for that celebrity.
