Celebrity Subscription System — Complete Technical Documentation for Replit Mobile App
1. How We Identify If a User Has Subscribed to a Celebrity
The single source of truth is the celebrity_favorites table.


{
  "table": "celebrity_favorites",
  "check_query": {
    "from": "celebrity_favorites",
    "select": "celebrity_id",
    "filters": {
      "user_id": "<profile.id of logged-in user>",
      "status": "active"
    }
  },
  "result": "Array of celebrity_id strings the user is subscribed to"
}
Frontend logic (used in /celebrities, /following, /wish-a-celebrity):


// Step 1: Fetch all active subscriptions for the user
const { data } = await supabase
  .from('celebrity_favorites')
  .select('celebrity_id')
  .eq('user_id', profile.id)       // profile.id = public.profiles.id
  .eq('status', 'active');

// Step 2: Build a lookup array
const subscriptions = data?.map(f => f.celebrity_id) || [];

// Step 3: Check any celebrity
const isSubscribed = (celebrityId: string) => subscriptions.includes(celebrityId);
Important: user_id in celebrity_favorites is NOT auth.users.id. It is profiles.id (the UUID from the public.profiles table). The platform consistently uses profile.id for all user-owned data.

2. Celebrity Favorites Table Schema

{
  "table": "celebrity_favorites",
  "columns": {
    "id": "uuid (PK, auto-generated)",
    "user_id": "uuid (FK → profiles.id) — the fan/subscriber",
    "celebrity_id": "uuid (FK → celebrities.id) — the celebrity",
    "status": "text — 'active' | 'inactive' | 'expired'",
    "price_paid": "integer — amount in INR (e.g., 499)",
    "payment_method": "text — 'wallet' | 'razorpay'",
    "referrer_commission": "integer — calculated on insert",
    "celebrity_commission": "integer — calculated on insert",
    "subscription_start_date": "timestamptz",
    "auto_renew": "boolean (default false)",
    "created_at": "timestamptz"
  },
  "unique_constraint": "(user_id, celebrity_id) when status = 'active'"
}
3. Celebrity Favorite Pricing Table
Each celebrity's subscription price is set by admin in a separate pricing table:


{
  "table": "celebrity_favorite_pricing",
  "columns": {
    "id": "uuid (PK)",
    "celebrity_id": "uuid (FK → celebrities.id)",
    "price": "integer — subscription price in INR",
    "referrer_commission_percentage": "integer (default 10)",
    "celebrity_commission_percentage": "integer (default 5)",
    "is_enabled": "boolean — if false, subscription is not available"
  },
  "query_to_get_price": {
    "from": "celebrity_favorite_pricing",
    "select": "*",
    "filter": {
      "celebrity_id": "<celebrity_id>",
      "is_enabled": true
    }
  }
}
Rule: If a celebrity has NO entry in celebrity_favorite_pricing OR is_enabled = false, they cannot be subscribed to. The UI shows "View Profile" instead of "Subscribe".
