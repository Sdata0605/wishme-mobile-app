/bookings Page — Complete Technical Specification for Replit Mobile App
1. PAGE PURPOSE
The /bookings page is the user's order history hub. It shows every order, generation, and creation the user has made across 12 different services. It uses a tabbed interface with lazy-loading — only the active tab's data is fetched. Tab badge counts are fetched upfront with lightweight head-only queries.

2. AUTHENTICATION
User must be logged in. The page uses useAuth() hook which provides profile.id (the user's UUID). All queries filter by user_id = profile.id.

6. COMPOSITE STATUS BADGE ENGINE (Celebrity Tab Only)
The celebrity tab uses a priority-based status engine checking 3 fields in order:

Priority (highest to lowest):
1. status === 'cancelled'           → "❌ Cancelled" (red)
2. video_status/generation_status === 'failed' → "⚠️ Failed" (red)
3. generation_status/video_status === 'timeout' → "⚠️ Timed Out" (orange)
4. status === 'completed'           → "✅ Completed" (green)
5. status === 'video_sent' or 'sent' → "📤 Delivered to You" (green)
6. generation_status === 'completed' AND video_status === 'ready' → "🎥 Video Ready — Pending Admin Review" (purple)
7. generation_status === 'uploading' → "⬆️ Uploading Video" (blue, PULSE)
8. generation_status === 'downloading' → "⬇️ Processing Video" (blue, PULSE)
9. generation_status === 'video_generating' → "🎬 Creating Video..." (blue, PULSE)
10. generation_status === 'script_generating' → "🤖 Writing Script..." (blue, PULSE)
11. status === 'confirmed'          → "✅ Confirmed — In Queue" (blue)
12. status === 'pending'            → "⏳ Awaiting Confirmation" (yellow)
PULSE = animated pulsing dot indicator for active processing states.

All other tabs use a simple status badge: completed → default, pending → secondary, failed/rejected → destructive.

7. TIMELINE STEPPER (Celebrity Tab Only)
A 6-stage horizontal progress bar shown only when status !== 'pending':

Stage 1: "Booking Placed"      → always completed=true
Stage 2: "Confirmed by Team"   → completed when status !== 'pending'
Stage 3: "Script Generated"    → completed when generation_status in ['video_generating','downloading','uploading','completed']
Stage 4: "Video Being Created" → completed when generation_status in ['downloading','uploading','completed']
Stage 5: "Video Ready"         → completed when video_status === 'ready'
Stage 6: "Delivered ✓"         → completed when status in ['video_sent','sent','completed']
Each stage: green circle with ✓ if completed, red circle with ✕ if failed, gray numbered circle if pending. Connected by horizontal lines (green if completed, gray if not).

8. PERFORMANCE OPTIMIZATIONS
Lazy tab loading: Only fetch data when tab is tapped. Cache with loadedTabs Set.
Head-only counts: 12 parallel queries returning only count, no data.
Selective columns: Each tab fetches only the columns used in UI.
Limit 20: Each query limited to 20 rows.
Database indexes: Composite (user_id, created_at DESC) on all 12 tables for O(log n) lookups.
Realtime targeted refetch: Supabase realtime channels on bookings and music_generations — only invalidates the specific tab, not all 12.
useMemo: Status engine and timeline functions are memoized.
9. REALTIME SUBSCRIPTIONS
Two channels filtered by user_id:

Channel 1: bookings UPDATE → invalidate 'celebrity' tab cache, refetch if active, refetch counts
Channel 2: music_generations UPDATE → invalidate 'music' tab cache, refetch if active, refetch counts

6. COMPOSITE STATUS BADGE ENGINE (Celebrity Tab Only)
The celebrity tab uses a priority-based status engine checking 3 fields in order:

Priority (highest to lowest):
1. status === 'cancelled'           → "❌ Cancelled" (red)
2. video_status/generation_status === 'failed' → "⚠️ Failed" (red)
3. generation_status/video_status === 'timeout' → "⚠️ Timed Out" (orange)
4. status === 'completed'           → "✅ Completed" (green)
5. status === 'video_sent' or 'sent' → "📤 Delivered to You" (green)
6. generation_status === 'completed' AND video_status === 'ready' → "🎥 Video Ready — Pending Admin Review" (purple)
7. generation_status === 'uploading' → "⬆️ Uploading Video" (blue, PULSE)
8. generation_status === 'downloading' → "⬇️ Processing Video" (blue, PULSE)
9. generation_status === 'video_generating' → "🎬 Creating Video..." (blue, PULSE)
10. generation_status === 'script_generating' → "🤖 Writing Script..." (blue, PULSE)
11. status === 'confirmed'          → "✅ Confirmed — In Queue" (blue)
12. status === 'pending'            → "⏳ Awaiting Confirmation" (yellow)
PULSE = animated pulsing dot indicator for active processing states.

All other tabs use a simple status badge: completed → default, pending → secondary, failed/rejected → destructive.

7. TIMELINE STEPPER (Celebrity Tab Only)
A 6-stage horizontal progress bar shown only when status !== 'pending':

Stage 1: "Booking Placed"      → always completed=true
Stage 2: "Confirmed by Team"   → completed when status !== 'pending'
Stage 3: "Script Generated"    → completed when generation_status in ['video_generating','downloading','uploading','completed']
Stage 4: "Video Being Created" → completed when generation_status in ['downloading','uploading','completed']
Stage 5: "Video Ready"         → completed when video_status === 'ready'
Stage 6: "Delivered ✓"         → completed when status in ['video_sent','sent','completed']
Each stage: green circle with ✓ if completed, red circle with ✕ if failed, gray numbered circle if pending. Connected by horizontal lines (green if completed, gray if not).

8. PERFORMANCE OPTIMIZATIONS
Lazy tab loading: Only fetch data when tab is tapped. Cache with loadedTabs Set.
Head-only counts: 12 parallel queries returning only count, no data.
Selective columns: Each tab fetches only the columns used in UI.
Limit 20: Each query limited to 20 rows.
Database indexes: Composite (user_id, created_at DESC) on all 12 tables for O(log n) lookups.
Realtime targeted refetch: Supabase realtime channels on bookings and music_generations — only invalidates the specific tab, not all 12.
useMemo: Status engine and timeline functions are memoized.
