/plan Page — Complete Technical Specification for Mobile App
1. Purpose
The Plan page is a subscription management screen where authenticated users view, compare, and upgrade between three membership tiers: Basic, Premium, and Elite. Each plan unlocks platform-wide service discounts and higher referral commission rates. Plans are a one-time purchase (not recurring).

2. Authentication
Requires authenticated user. Redirects to /auth if not logged in.

3. Database Schema
plans table
Column	Type	Description
id	uuid	Primary key
name	text	basic, premium, or elite
price	integer	Plan price in INR (e.g. 50, 499, 999)
original_price	integer (nullable)	Strikethrough price for showing discount
discount_percentage	integer	Display discount (e.g. 50%)
features	jsonb	Array of feature strings
referral_commission_l1	integer	Level 1 referral %
referral_commission_l2	integer	Level 2 referral %
service_discount_percentage	integer	Discount on all services (0%, 10%, 15%)
is_popular	boolean	Highlights the card with border + scale
is_active	boolean	Only active plans are shown
profiles table (relevant columns)
Column	Type	Description
id	uuid	Profile ID (primary user identifier)
plan	enum (basic, premium, elite)	User's current plan
referred_by	uuid (nullable)	FK to referrer's profile
wallet_balance	integer	Current wallet balance
4. The Three Plans — Detailed Comparison
Feature	Basic (₹50)	Premium (₹499)	Elite (₹999)
Service Discount	0%	10%	15%
Referral L1 Commission	5%	10%	15%
Referral L2 Commission	2%	5%	7%
is_popular	false	true	false
Icon	Star	Zap (lightning)	Crown
How service discounts work platform-wide:
Basic user pays full price for everything (bookings, greeting cards, photo wishes, voice calls, UGC videos, image promotions, music generation)
Premium user gets 10% off every service. E.g., a ₹500 booking costs ₹450
Elite user gets 15% off every service. E.g., a ₹500 booking costs ₹425
The discount is calculated by the usePlanDiscount hook:


getDiscountedPrice(basePrice) = Math.round(basePrice * (1 - discountPercentage / 100))
How referral commissions work:
When a referred user completes any paid transaction (booking, wish order, photo wish, voice call, music, UGC, image promotion, or plan upgrade), PostgreSQL triggers automatically calculate and distribute commissions:

L1: Direct referrer gets their plan's L1 percentage of the transaction amount
L2: The referrer's referrer gets their plan's L2 percentage
Example: Elite user refers User B, who books ₹1000 service → Elite user earns ₹150 (15% L1). If Elite user was referred by User A (Premium), User A earns ₹50 (5% L2).

7. User Scenarios
Scenario A: New user (no plan / basic by default)
Sees all 3 plan cards
Can select any plan
After selecting, profile.plan updates
All services charge full price (0% discount)
Referral commissions: 5% L1, 2% L2
Scenario B: User purchases Premium (₹499)
Now sees only Premium and Elite cards (Basic is filtered out)
Premium button shows "Current Plan" (disabled)
All services get 10% discount automatically via usePlanDiscount hook
Referral commissions upgrade: 10% L1, 5% L2
Trigger fires: process_plan_referral_commission() — if user was referred, the referrer gets L1 commission on ₹499, and referrer's referrer gets L2
Scenario C: User upgrades to Elite (₹999)
Now sees only Elite card
Header shows "Congratulations! You're already on our highest plan"
All services get 15% discount
Referral commissions: 15% L1, 7% L2
Same referral trigger fires on the ₹999 amount
Scenario D: User skips plan selection (from modal)
PlanSelectionModal with canSkip={true} shows "Skip for now" button
User stays on default basic plan
Gets 0% discount, 5%/2% referral rates
Can upgrade anytime from /plan page or sidebar
8. Automatic Referral Commission on Plan Upgrade (PostgreSQL Trigger)
The trigger process_plan_referral_commission() fires on UPDATE of profiles when plan changes from basic to premium or elite:

Looks up profiles.referred_by to find L1 referrer
Gets the referrer's plan tier to determine their commission rates
Calculates plan_price * L1_rate / 100
Inserts into referral_transactions and wallet_transactions
Repeats for L2 (referrer's referrer)
Example: User upgrades to Premium (₹499), referred by Elite user:

Elite referrer earns: ₹499 * 15% = ₹74 (L1)
If Elite user was referred by a Premium user: ₹499 * 5% = ₹24 (L2)

12. Mobile Integration Notes
Add Razorpay before profile update: The web app currently updates the plan directly. For mobile, integrate the Razorpay native SDK between plan selection and profile update (see Section 6).
Plan filtering: Only show plans >= user's current plan. Use the filter logic: if current is premium, show premium + elite only.
Downgrade prevention: There is no downgrade flow. Once upgraded, the user cannot go back.
Wallet alternative: You could also allow wallet payment for plans — deduct from wallet_balance and insert a wallet_transactions record with transaction_type: 'plan_purchase' before updating the profile.
The features column is JSONB — parse it as a string array for display.
Referral trigger is automatic: No client-side code needed for commission distribution. The PostgreSQL trigger handles everything when profiles.plan is updated.
