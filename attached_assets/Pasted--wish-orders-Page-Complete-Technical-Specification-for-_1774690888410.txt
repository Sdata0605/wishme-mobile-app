/wish-orders Page — Complete Technical Specification for Replit Mobile App
1. PAGE PURPOSE
This page shows the authenticated user all their "Wish a Celebrity" orders — greeting cards they've created and sent (or are still processing) for celebrities on special occasions. It splits orders into two visual sections: Active/Pending and Completed.

2. AUTHENTICATION & USER ID
CRITICAL: The user_id column in wish_celebrity_orders stores the Profile UUID (profiles.id), NOT the Auth UUID.

Step 1 — Resolve Profile UUID after login:

GET /rest/v1/profiles?user_id=eq.{AUTH_UUID}&select=id
Headers: apikey, Authorization: Bearer {session.access_token}
Response: [{ "id": "profile-uuid-here" }]

Use this profiles.id for ALL queries below.

3. SINGLE API ENDPOINT — DATA FETCH
There is only ONE query on this entire page. No tabs, no lazy loading needed.

Endpoint:

GET /rest/v1/wish_celebrity_orders?user_id=eq.{PROFILE_ID}&select=*,celebrities(id,name,image_url)&order=created_at.desc
Headers:

apikey: {SUPABASE_ANON_KEY}
Authorization: Bearer {access_token}
Full Response Shape (array of objects):


[

4. CLIENT-SIDE FILTERING (No separate queries)
Split the single response array into two lists using local filters:


// Section 1: Active/Pending
const pendingOrders = orders.filter(order => 
  order.payment_status === 'completed' && order.status !== 'sent'
);

// Section 2: Completed
const completedOrders = orders.filter(order => 
  order.status === 'sent'
);
5. UI STRUCTURE & COMPONENTS
5A. Header Section
Element	Details
Title	"My Wish Orders" — bold, large
Subtitle	"Track your celebrity wishes and greeting cards" — muted
CTA Button	"Make New Wish" → navigates to /wish-celebrity
5B. Empty State
If orders.length === 0: Show a centered Card with text "No wishes yet" and a Button "Create Your First Wish" → /wish-celebrity.

5C. Section 1 — Active/Pending Orders
Only renders if pendingOrders.length > 0.

Section Header: Spinner icon (orange) + text "Active/Pending Orders"

Each Order Card (orange-tinted border):

UI Element	Data Key	Notes
Avatar (circle, 64px)	order.celebrities.image_url	Fallback: /placeholder.svg
Celebrity Name	order.celebrities.name	Bold, large
Occasion + Recipient	order.occasion_type + order.recipient_name	Format: "Birthday • To: John"
Status Badge	order.status	Color mapping below
Message Preview	order.message	2-line clamp
"Continue Wish" Button	—	Navigate to /wish-confirmation/{order.id}
"View Card" Button	order.generated_card_image_url	Only if URL exists. Opens in new tab
Processing Indicator	—	Only if order.status === 'processing'. Shows spinner + "Generating your card..."
5D. Section 2 — Completed Wishes
Only renders if completedOrders.length > 0.

Section Header: Green checkmark badge + text "Completed Wishes"

Each Order Card (green-tinted border):

UI Element	Data Key	Notes
Avatar (circle, 64px)	order.celebrities.image_url	Fallback: /placeholder.svg
Celebrity Name	order.celebrities.name	Bold
Occasion + Recipient	order.occasion_type + order.recipient_name	Same format
Status Badge	Fixed green "Sent"	Always green
Message Preview	order.message	2-line clamp
"View Conversation" Button	—	Navigate to /messages
"View Card" Button	order.generated_card_image_url	Only if URL exists. Opens in browser
"Download" Button	order.generated_card_image_url	Only if URL exists. Downloads as wish-card-{order.id}.jpg
6. STATUS BADGE COLOR MAPPING

function getStatusColor(status) {
  switch (status) {
    case 'completed': return 'default';    // solid dark
    case 'processing': return 'secondary'; // gray
    case 'pending': return 'outline';      // bordered
    default: return 'outline';
  }
}

9. PERFORMANCE TIPS FOR MOBILE
Single query — this page only makes 1 API call, so it's already fast
Select only needed columns to reduce payload:
select=id,status,payment_status,occasion_type,recipient_name,message,generated_card_image_url,created_at,celebrities(id,name,image_url)
Add limit=50 to prevent loading hundreds of orders
Cache the response — don't re-fetch on back navigation
Lazy-load celebrity avatars using thumbnail/placeholder pattern
